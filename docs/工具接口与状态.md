# 工具接口与状态

这是首版接口与状态约定。命令行原型已在 ../agent_baseline/app.py 实现，JSON Schema 位于 ../configs/operation_plan.schema.json。规则规划器已跑通端到端链路；Qwen3-VL 在图片 1 已做一轮真实推理和渲染，正式基线评测仍待开展。

## 状态设计

保留原图引用、当前设置、撤销用的状态快照、最近文字对话和结果版本。每个工具显式 enabled；祛痘另有 sensitivity，其余三个工具为 strength。状态快照用于 undo；文字对话用于理解“再加一点”“把它关了”，Qwen 入口现传入最近 4 轮对话。

初始状态见 ../configs/tool_registry.json。全部工具默认关闭。强度 0 不是百分比；祛痘敏感度 0 仍可能执行检测，必须以 enabled 判断是否调用。

祛痘初始虽关闭，状态仍预置 `sensitivity=0.5`，这是以后开启时可用的默认值，并不表示当前正在祛痘。若曾以 0.3 开启后关闭，则保存 0.3；关闭时不传 `--remove-acne`，再次开启可沿用或改写这个值。

## 模型输出

~~~json
{
  "action": "update",
  "updates": [
    {"tool": "enlarge_eyes", "enabled": true, "strength": 0.2}
  ],
  "question": null
}
~~~

- update：仅更新列出的工具，其他当前状态完全保留。
- undo：恢复上一步完整状态；updates 为空。
- reset：恢复所有工具关闭的初始状态；updates 为空。“回到最初”也执行 reset。
- clarify：不执行、不改状态，返回一个明确问题；updates 为空。

“撤销大眼，瘦脸保留”是把 enlarge_eyes 设为 enabled=false、strength=0 的 update；不是全局 undo。“撤销上一步”才是 undo。

新状态校验成功后，始终从原图重新渲染。首次就固定原图的人脸/区域分析结果和实际执行顺序；先与上游一致地处理皮肤，再做组合形变。不能每一轮在已变形 JPEG 上继续叠加。

## 四工具到上游参数的映射

| tool | 参数 | 启用时 CLI 参数 | 关闭 |
| --- | --- | --- | --- |
| slim_face | strength∈[0,1] | --slim-face VALUE | 不传该参数 |
| enlarge_eyes | strength∈[0,1] | --enlarge-eyes VALUE | 不传该参数 |
| remove_acne | sensitivity∈[0,1] | --remove-acne VALUE | 不传该参数 |
| smooth_skin | strength∈[0,1] | --smooth-skin VALUE | 不传该参数 |

这张表已由 agent_baseline/app.py 使用，四张图片上的工具调用均已跑通；效果细节仍需后续优化。

用户现定“痘痘全部去除”的操作语义：仅开启 remove_acne，sensitivity=1.0，修复该敏感度下检测出的所有候选点。sensitivity 决定圈选范围，不是每个点的修复力度；现有祛痘工具没有单独的 strength。分析叠加图默认 sensitivity=0.5，与按 1.0 编辑时重新检测的圈点可能不同。这个操作不保证所有真实痘痘消失，完成反馈应说明实际检测/修复数与可能残留。

首版只接受单一处理对象；分析发现多人时不默认处理所有人，应要求单人人像或后续增加明确选择。

## 执行前检查与语义评测

1. 运行时校验器检查 action、tool、字段、类型、有限数值和 0–1 范围；禁止未知字段、重复工具及不合法的 action/updates/question 组合。
2. 状态合并只更新计划列出的字段；undo 检查是否有可撤销的历史，reset 使用初始状态。
3. 场景与执行层检查原图、单人目标、工具实际执行、warnings 与输出；关闭的工具不传 CLI 标志，参数只从受检字段构造。
4. 中文指令是否被正确理解，通过**模型原始计划与人工审核标签**独立评测；“只大眼”“不要磨皮”“含糊指代应澄清”等错误归因于模型，不靠关键词门禁代替模型判断。

运行时 `validate()` 不再用中文关键词判断计划是否获授权。结构合法但语义错误的计划可能进入执行，所以必须保存原始计划、实际执行及用户可撤销的状态，并在评测中如实计错。规则规划器 `rule_plan()` 仍是单独的基线规划方式，不审查 Qwen 输出。JSON Schema 自身不保证同一工具不重复，也不证明语义正确；前者由程序检查，后者由独立评测检查。

## 拒绝与失败

- 不合法或超范围计划：不修改状态，不执行部分操作，保存原因。
- 无人脸/多目标/执行超时：不报告美颜成功；保留原状态与错误。
- 部分工具实际跳过：不把请求状态当实际成功，展示具体项目并记录，避免用户误认为已修好。
- 对话历史、模型计划、受检计划、请求设置、实际执行和输出图分别保存。
- undo/reset 属于确定性会话动作，不需要训练一个修图算法来反向还原图像。

## 初步程度策略

用户于 2026-11-21 确认：普通开启指令没有给程度时，对应工具参数设为 0.5；“明显磨皮”设为 0.7；没有明确目标值的“再加一点/调淡一点”等相对要求，在当前值上加/减 0.1，并限制在 0–1。明确轻微、常规、最高等词仍按提示词中的对应档位解释。`皮肤好点` 同时开启磨皮 0.5 与祛痘敏感度 0.5。只更新提到的工具；关闭祛痘时保留敏感度数值，不执行祛痘。

用户于 2026-11-25 进一步确认：大眼已经开启、强度 0.5 时说“轻微大眼”，直接把大眼设为轻微档位 0.2；这是明确程度目标，不是相对减轻 0.1，也不是增加 0.1。其他工具在已开启状态下使用“轻微”的目标值，待单独确定。

用户于 2026-11-22 补充边界：瘦脸、大眼、磨皮已开启且强度为 0.1 时，若只说“再减一点/退一格”等相对减弱，减 0.1 会得到无效果的 0.0，规划器须先 `clarify`，`updates=[]`，询问是否关闭该工具。本轮不改设置、不渲染；同意后下一轮用 `enabled=false, strength=0` 关闭，不同意则保持原值。此规则属于模型语义规划，不扩充运行时校验器的中文关键词拦截。祛痘 `sensitivity=0` 仍按原规则，不等于关闭。

这些是操作计划标签约定，不等于已验收的图像效果；尤其敏感度 1.0 不能保证去掉全部真实痘痘。模型先学习少量稳定档位，暂不自由生成复杂空间坐标。

保存状态版本、工具接口版本与档位版本，避免工具升级后旧标注不再适用。
