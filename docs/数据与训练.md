# 数据与训练

## 训练对象

候选为 Qwen3-VL-2B-Instruct 的语言侧 LoRA；视觉部分和其余基座冻结。关键点/分割和修图工具先复用。首版只有 SFT 为计划主线，尚未执行。具体训练框架在服务器检查现有环境后选择一个兼容入口，不并行搭建多套框架。

先测原模型加工具说明的基线，再判断 SFT 是否改善，不预设训练必然有用。图片可见性也应核实：若样本实际上只依赖文本，不能据此宣称学到了细粒度视觉美颜判断。

## 一条样本包含什么

| 字段 | 含义 |
| --- | --- |
| sample_id / image_id / subject_id / source_group | 追踪、人物与来源隔离 |
| image_ref | 相对路径与原图 SHA256 |
| current_state | 四工具现有 enabled 与参数 |
| history | 理解“刚才/再轻一点”所需的最近文字对话；当前 Qwen 推理入口传最近 4 轮 |
| instruction | 用户本轮中文指令 |
| expected_plan | action、updates、question，遵循接口 Schema |
| annotation_source / review_status | 标签来自谁、是否复核 |
| split / tools_version | 划分与工具/档位版本 |

真实训练导出后由 processor 读取图片，模板提供工具说明、当前状态与最近文字对话，assistant 监督正确计划；训练输入格式必须与当前 Qwen 推理提示词一致。不要让相对图片路径文本冒充实际视觉输入。图片渲染结果可以用于审核工具与标签，不是本项目的像素生成监督目标。

## 标签怎么来

1. 先验证工具和程度档位。
2. 选择有来源记录的人像，指定可执行的操作和明确限制。
3. 写自然指令与正确更新，必要时工具渲染后核对标签是否合理。
4. 扩充等价说法，但防止改写改变程度、否定或指代。
5. 模型生成仅做候选，检查后才进入训练；不把它自己的答案当独立金标准。
6. 不依赖用户用醒图手工制作大量前后对，也不把 Lightroom XMP 参数改名成瘦脸/大眼标签。

## 样本覆盖

- 同义：脸小点/脸颊收一点→瘦脸。
- 单工具与组合：大眼、祛痘；大眼加瘦脸。
- 否定：只大眼、不磨皮；祛痘但不瘦脸。
- 程度：稍微、再轻一点、保持自然，按冻结档位政策标注。
- 保留：已有瘦脸，增加大眼时不能清空瘦脸。
- 撤销：关闭大眼但保留其他；撤销上一步；全部重置。
- 澄清：多种已有效果后说“这个去掉”、不支持的头包脸、互相矛盾的要求。
- 失败/不可用：没有合适人脸时不声称成功。

模糊“自然一点”没有唯一答案，不强行制造自信标签。教学样例不等于完整语言覆盖。

本轮用户允许放宽图片适配：指令到操作计划的样本不要求可见痘痘或皱纹。此类样本只评估选择四工具、参数及状态更新；祛痘/磨皮的视觉效果验收仍需可见目标或可核对细节的专门图片。首版没有独立去皱工具。儿童外观、背景人物等图片可暂作计划候选，但不自动选作美颜视觉效果验收图。

## 划分

以人物、原图、来源组为边界先划分，再生成改写和处理版本。同一人不同照片也不跨集合。无法识别人物关联的数据记录不确定性，不宣称完全无身份泄漏。2026-11-21 新包增加 FFHQ 与 CelebAMask-HQ 原图各 50 张，FFHQR 不用。加上用户直接上传的 `FFHQ/00001.png`，当前 141 张原图清单见 `agent_baseline/dataset_prep/new150/image_splits_v4_141.jsonl`：train 100、dev 20、test 20；1 张实际单脸但工具把手误检为第二张脸，暂排除工具运行。旧 40 张分区不变；CelebAMask-HQ 12/13 同组，旧 5 号与新增 66 号视觉初审同人并同组。105 条文字候选暂绑并覆盖 100 张训练图；旧题目连同新增图的一图一题，现有 dev 22 条、test 22 条计划候选，分别覆盖各自 20 张图片；题目均在 `agent_baseline/dataset_prep/review_v4/`。用户在聊天中对复核表 185 行统一确认“全都通过”；开发/测试各 22 条计划题已冻结，产物与来源哈希在 `review_v4/frozen/`，原 Excel J/K 保持空白。暂排除的 1 图仍不用于工具执行。此通过仅用于计划题和图片分区复核，不表示图像修复效果通过；105 条训练文字绑定仍 `eligible_for_training=false`。跨来源人物身份隔离仍缺独立证明。

原图 SHA、近重复与来源检查是互补的；仅 SHA 不同不能证明人物独立。冻结 test 后不依据它修提示词/标签/模型；开发问题用 dev 分析。

先从少量探索数据起步，记录真实数量。不用大量同一照片的指令改写冒充大规模独立人像数据。

## 训练记录

基座与 tokenizer/processor 来源和版本、环境、视觉输入、模板、训练文件 SHA、LoRA 注入模块/rank/alpha、种子、精度、批量与累计、步数、可训练参数、实际消费样本与监督 token、截断、显存口径、耗时和 checkpoint。

先做真正的模板与单步加载/更新验证，再开展有限正式训练。没有 GPU 时可继续设计与适配，不启动假训练或伪造训练结果。

## RL 的边界

当前不生成 RL 数据、不设计大型奖励模型。后续若明确加入，可对同一输入采样少量计划，执行后按可信任务指标给奖励。需防止“什么都不做”靠身份保持拿高分，及过度变形迎合尺寸指标。规则分不代表审美金标准，同模型评价不等于独立评估。

DPO偏好样本与在线GRPO轨迹分别表述；有离线排序数据不代表已做RL。由真实基线问题决定是否增加这一阶段。
